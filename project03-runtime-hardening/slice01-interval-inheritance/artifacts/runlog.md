## Contract readback before dependent edits/checks

The accepted public contract is a stable 15-function/11-type API with calendar-style exports retained, existing tuple/binary/list behavior and error shapes preserved, EDoc conventions retained, and compatibility down to the repository’s intended old Erlang floor. This slice changes only private interval classification/reconstruction and the three named source/test/README paths. The only current finding IDs to repair are ERL-CAL-003/P03-01 and ERL-CAL-004/P03-02; all other seven accepted findings remain open and must be carried through applicability replay.

`resolve_end/2` currently sends unsigned four-digit starts to `parse_endpoint/1` but fails to recognize a complete `+`-signed positive year, while fixed-width raw `extract_year/1`/`extract_year_month/1` truncate the token. Classification and extraction therefore need one policy: preserve raw signed token through the first date delimiter (or end of string), retain the ordinary four-digit unsigned path, route complete signed endpoints independently, and continue rejecting negative-year interval endpoints and basic-date-start abbreviations. Year-month reconstruction must account for the actual token length and separator/month suffix.

For abbreviated endpoints, first reconstruct the end’s local date using the raw start’s local date/year/month; only then apply the raw start timezone if the end omits a zone. A zone is discoverable only after `T`, so date hyphens and signed year signs cannot be treated as timezone markers. Explicit end `Z`/`+`/`-` overrides inheritance, and complete endpoints remain independently parsed. A date-only abbreviated end means midnight. Crucially, when adding an inherited zone, complete abbreviated local time to seconds first: date-only to midnight, `HH` to `HH:00:00`, `HH:MM` to `HH:MM:00`, and T-prefixed basic `HHMM` to `HHMM00` only when all characters are digits. Pass existing second and fractional forms through unchanged. Do not append a zone without this local completion: standalone minute+zone parsing is a known trap; bare four digits remain a full-year endpoint. With no start zone preserve legacy parsing. Do not use normalized UTC start dates to derive rollover ends, send float datetimes into CAL002 arithmetic, change the standalone timestamp parser, or round fractions via formatting.

Observable proof will use exact public interval tuples/bounds for signed short/padded/large and formatted-year cases; independent timezone arithmetic for positive/negative offsets, explicit zone overrides and explicit full ends; raw-date rollover across midnight and year 10000; fractional `.125`; minute/hour/basic-time and day/month-day midnight cases; semantic parse→format_interval→parse equality; and malformed, negative-year, basic-start, month-day+time and year<=0/nonzero-zone negative controls.
